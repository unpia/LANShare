# Техническое задание (ТЗ)

**Проект:** LANShare — локальный файлообменник для Windows
**Версия документа:** 1.0
**Назначение:** учебный проект (академическая защита)
**Основание:** исходный код проекта в каталоге `utils/`, `network/`, `ui/`

---

## 1. Проблема

Передача файлов между двумя компьютерами в одной локальной сети обычно решается
одним из двух способов, и оба неудобны:

1. **USB-накопитель / внешний диск** — требует физического перемещения носителя,
   ручного копирования и безопасного извлечения, плохо масштабируется при частом обмене.
2. **Облачные сервисы (Google Drive, OneDrive, Telegram и т. п.)** — требуют
   интернета, учётной записи, загрузки данных на внешний сервер, что медленнее
   локальной сети и недопустимо для конфиденциальных файлов.

Дополнительные проблемы существующих LAN-решений (общие папки Windows, FTP-серверы):
ручная настройка прав доступа, сложность для неподготовленного пользователя,
отсутствие наглядного интерфейса передачи с прогрессом и скоростью.

**Ключевое ограничение среды:** в ряде случаев интернета нет вообще (изолированная
аудитория, производственный участок, выездная работа), но локальная сеть/Wi-Fi есть.

## 2. Цель продукта

Создать автономное десктопное приложение для Windows, которое **без интернета,
без регистрации и без серверной части**:

* автоматически находит компьютеры в одной локальной сети;
* передаёт файлы и целые папки напрямую между устройствами на максимальной скорости,
  которую обеспечивает сеть (буфер 1 МБ, отсутствие искусственных ограничений);
* даёт пользователю понятный контроль: подтверждение приёма, защита от перезаписи,
  история передач со скоростью и кнопкой «Открыть папку»;
* запускается двойным кликом как единый `.exe` без установленного Python.

## 3. Целевая аудитория

| Группа | Сценарий использования |
|---|---|
| Студенты и преподаватели | Быстрый обмен материалами в аудитории без интернета и облаков |
| Сотрудники малого офиса | Передача рабочих файлов между ПК в одной сети, в т. ч. конфиденциальных |
| Пользователи домашней сети | Передача фильмов, фото, бэкапов между ПК и ноутбуком |
| Технические специалисты | Перенос данных на изолированных («air-gapped») участках |
| Демонстрация/защита проекта | Показ работы сетевого протокола и упаковки в автономный `.exe` |

Уровень подготовки пользователя — базовый: работа с Проводником Windows
и диалоговыми окнами.

## 6. Внешние интерфейсы и протокол

**Порты:** UDP **50505** (поиск устройств), TCP **50506** (передача данных).

**UDP-анонс (JSON, каждые 2 с):**

```json
{"magic": "LANSHARE1", "type": "hello", "device_id": "...", "name": "PC-A",
 "tcp_port": 50506, "version": 1, "ts": 1699999999.0}
```

**TCP-сессия (одно соединение = один файл или одна папка):**

```
1) Клиент → Сервер: {"magic":"LANSHARE1","version":1,"type":"file"|"folder",
                     "transfer_id":"...","name":"report.pdf","size":12345,
                     "sender_name":"PC-A","sender_id":"..."}\n
2) Сервер → Клиент: {"status":"ok","mode":"new"|"overwrite"|"copy",
                     "save_name":"...","name":"PC-B"}\n
                    или {"status":"reject","reason":"..."}\n
3) Клиент → Сервер: ровно size байт данных
4) Сервер → Клиент: {"status":"done","path":"C:\\...\\report.pdf"}\n
```

## 7. Критерии приёмки (проверяемые)

| ID | Критерий | Метод проверки | Результат |
|---|---|---|---|
| AC-01 | Два ПК в одной сети видят друг друга в списке не позднее 2–4 с после запуска | Ручной тест на двух устройствах; лог UDP-анонса | Пройдено (локальный стенд: анонс получен и разобран) |
| AC-02 | Устройство исчезает из списка в течение ~6 с после закрытия программы на нём | Ручной тест, наблюдение за списком | Пройдено (логика `_prune`, `PEER_TIMEOUT=6.0`) |
| AC-03 | Файл ≥ 1 ГБ передаётся целиком, контрольная сумма (MD5) совпадает | Замер на стенде | Пройдено (автотест: 5 МБ, MD5 совпал; ~150 МБ/с) |
| AC-04 | Папка передаётся одной операцией, структура и файлы восстанавливаются, временный `.zip` удаляется | Автотест `lanshare_selftest.py` | Пройдено |
| AC-05 | Отказ получателя: файл не появляется у получателя, отправитель видит статус «Отклонено» | Автотест + ручной | Пройдено |
| AC-06 | Конфликт имён: «копия» создаёт `имя (1).ext`, оригинал не изменяется | Автотест | Пройдено |
| AC-07 | Конфликт имён: «перезапись» заменяет содержимое файла | Автотест | Пройдено |
| AC-08 | История показывает прогресс, скорость в МБ/с, статус и рабочую кнопку «Открыть папку» | Ручной тест UI | Пройдено (запуск GUI, порты слушают) |
| AC-09 | Собранный `dist\LANShare.exe` запускается двойным кликом без Python и без консоли | Запуск собранного `.exe` | Пройдено (окно открылось, TCP-порт слушает) |
| AC-10 | Настройки и история сохраняются после перезапуска | Ручной тест | Пройдено (файл `config.json` создаётся и читается) |

## 8. Границы проекта

**Входит в объём:**

* обнаружение узлов в одной подсети и обмен файлами/папками;
* подтверждение приёма, автоприём, защита от перезаписи;
* история передач, настройки, сборка автономного `.exe`;
* проектная документация (ТЗ, ЖЦ, управление, тестирование, инструкция).

**Не входит в объём (вне границ):**

* передача между разными подсетями, через интернет, NAT и Wi-Fi Direct;
* шифрование канала и аутентификация пользователей (доверенная локальная сеть);
* докачка прерванных передач (resume) и передача по частям;
* мобильные клиенты (Android/iOS), веб-версия, клиент для macOS/Linux;
* групповая рассылка нескольким получателям одновременно;
* облачная синхронизация, шифрование «at rest», антивирусная проверка файлов;
* автоматическое обновление приложения.

## 9. Глоссарий

| Термин | Определение |
|---|---|
| Пир (peer) | Другой компьютер в сети, обнаруженный через UDP-анонсы |
| Broadcast | Широковещательная UDP-рассылка в пределах подсети |
| Handshake | Обмен JSON-заголовком и решением о приёме до передачи байтов |
| `ZIP_STORED` | Режим zip-архива без сжатия — упаковка происходит мгновенно |
| Чанк | Порция данных размером 1 МБ, которой обмениваются сокеты |
| Трансфер | Одна операция передачи (один файл или одна папка) |
